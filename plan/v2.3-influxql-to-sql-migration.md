# PRD — InfluxQL → SQL migration (snapshot pipeline)

**Status:** Shipped
**Owner:** unassigned
**Related:** [V2 master plan](./v2.md).

## Context

The stats backend moved from InfluxDB 3 Core to TimescaleDB. The public
InfluxQL HTTP endpoint (`https://owstats.jhiggins.tech/query?...`) that V2
queried directly from the browser was retired (it now returns `410 Gone`).
The replacement is read-only SQL over the standard Postgres wire protocol
(`owstats.jhiggins.tech:5432`, database `ow_stats`, intentionally public
read-only credentials).

Browsers cannot speak the Postgres wire protocol, and the server
intentionally runs no HTTP query gateway — so "translate the query strings"
was never an option. The data flow itself had to change.

## Decision

Bake **JSON snapshot datasets** in CI and serve them as static files next to
the SPA. The scraper upstream samples hourly, so an hourly refresh loses no
effective freshness versus the old live queries.

```
TimescaleDB ──(SQL, hourly CI)──▶ docs/data/snapshots/*.json ──(fetch)──▶ SPA
```

- `web-v2/scripts/fetch-snapshots.mjs` — connects with `pg`, runs the SQL
  (metric-per-row schema pivoted back into typed rows), writes the datasets:
  `meta`, `rank-current`, `rank-daily`, `career-latest`, `career-daily`,
  `career-hero-daily`, `profiles`.
- `.github/workflows/refresh-data.yml` — hourly cron; writes straight into
  `docs/data/snapshots/` and commits with `[skip ci]` (no site rebuild
  needed; the SPA fetches these files at view time).
- `deploy.yml` — seeds snapshots from the previous deploy, then refreshes
  them (`continue-on-error`) so a backend outage can't block a deploy.
- Client: `lib/snapshotClient.ts` replaces `lib/influxClient.ts` (same
  session-cache + stale-fallback + StaleBanner behavior, plus a "pipeline
  looks stuck" check against `meta.generatedAt`). Every query module keeps
  its exported signature and result shape but now filters/aggregates the
  snapshot rows client-side.

## Why datasets, not precomputed chart payloads

Aggregation stays client-side (per-player rows in, team roll-ups out) so the
hidden-players setting keeps working without refetching, and UI tweaks don't
require pipeline changes.

## Accepted granularity changes

- Raw samples only survive 14 days server-side; anything historical comes
  from the daily table (last sample per series per UTC day, 600 days).
- The player rank trend chart therefore moved from 1-hour to 1-day buckets
  over its 90-day window.
- Weekly (hero usage/perf) buckets are rolled up client-side from the daily
  rows; buckets are epoch-aligned rather than InfluxQL's Thursday-aligned
  weeks.
- Season-start detection is day-resolution (daily table) instead of
  raw-sample resolution.

## Out of scope

- OverFast API usage (hero meta, player summaries) — unchanged, still
  browser-direct with open CORS.
- Any server-side HTTP gateway for live SQL from the browser.
